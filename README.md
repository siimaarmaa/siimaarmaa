## 👋 About Me

I'm a systems administrator and DevOps-focused infrastructure enthusiast with a strong interest in Linux, automation, networking, self-hosted services and reliable infrastructure.

I enjoy working on the parts of technology that usually sit behind the scenes — servers, operating systems, networks, containers, monitoring, backups and automation.

My homelab is a big part of that.

It gives me a place to build and operate real infrastructure, experiment with new technologies, automate repetitive administration tasks and learn by actually running things rather than only reading about them.

I like systems that are:

- Reliable
- Reproducible
- Observable
- Secure
- Automated
- Easy to maintain

And preferably boring once they're working.

### Troubleshooting

When something breaks, I prefer finding the actual cause instead of repeatedly restarting the service until it happens to work.

My usual approach is:

1. Identify the symptoms
2. Check the logs
3. Verify the system state
4. Narrow down the failure
5. Fix the underlying problem
6. Automate or document the solution where appropriate

# 🚀 DevOps

For me, DevOps is less about collecting a large number of tools and more about improving how infrastructure and software are built, deployed and maintained.

A typical workflow looks something like:

**Code → Version Control → Automation → Deployment → Monitoring → Feedback**

The specific tools can change.

The underlying goal doesn't:

**make changes repeatable, observable and less dependent on manual intervention.**

# 🧠 Infrastructure Philosophy

### Automate

Repetitive work should not depend on someone remembering how to do it.

### Document

If the only person who understands a system is the person who built it, the system has a problem.

### Monitor

You should know something is broken before someone else tells you.

### Back Up

A backup that has never been restored is an assumption.

### Keep It Simple

Every additional component is another component that eventually needs to be maintained.

### Understand the Stack

Using a tool is useful.

Understanding what the tool is actually doing is better.
